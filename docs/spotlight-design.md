# DevKit Spotlight 设计

## 2026-10-10 命令入口修复

- 公开入口为 `Base64 命令`、`Base64 编码或解码`、`DevKit 命令`、`DevKit 工具操作`。Base64 独立命令入口的隐藏标记已移除；单独的旧编码/解码动作继续隐藏以避免重复。
- `Base64 命令` 作为工具上下文，接受系统 Quick Key 后面的 `encode 123`，也接受完整的 `base64 encode 123` 或已配置别名。共用命令解析器，保留原文空格、Unicode 和尾部换行，遵循总开关和 Base64 工具开关。它不会被另一工具名重定向。
- 第一次在 Spotlight 操作列表搜索 `Base64 命令`（来源 DevKit），为其设置快捷短语 `base64`，之后才使用 `base64 encode 123`。未设置快捷短语时可先选中动作，再填写 `encode 123`。需要选择操作的流程使用 `Base64 编码或解码`。
- 应用里的命令别名与系统快捷短语是两个配置。其他工具继续通过 `DevKit 命令` 的完整命令或 `DevKit 工具操作` 的动态选择使用；例如给通用命令入口设置 dk 后使用 `dk json format {}`。
- 开关控制索引、动态可选工具和执行权限，不能让编译期动作名称立即从系统目录消失。关闭时解析和执行均拒绝处理；只清理本应用索引，不重建系统数据库。
- 构建号更新为 2。`Scripts/check-spotlight-metadata.py <DevKit.app>` 检查四个公开后台动作、完整的必需参数摘要及 App Shortcuts。52 项测试通过，包含独立命令上下文与用户示例的尾部换行。
- 用户系统实测已确认可发现独立动作。此前的执行失败已定位到临时签名缺少 Team ID；用户创建 Apple Development 证书并补齐官方 WWDR G3 证书链后，开发者签名版已安装。`linkd` 日志确认接受 autoShortcut 与 mediator 连接，进程注册及参数更新成功。A/B 的结果卡片与复制完整交互仍由用户自行验证。

## 已确认的体验

Spotlight 是工具箱的快捷入口。用户要求命令式 B 与引导式 A 同时存在，B 优先；接受首次手动设置关键词；执行后直接展示结果，点击结果复制。主窗口不因普通快捷动作而弹到前台。

| 模式 | 用户动作 | 预期 |
| --- | --- | --- |
| B 编码 | 输入 `base64 encode hello`，执行 | 显示 `aGVsbG8=`，点击复制 |
| B 解码 | 输入 `base64 decode MTIzMTIzMTIzYXNkZmFkc2ZzZGFmCg`，执行 | 显示解码文本，复制值保留最后的 LF |
| A 引导 | 输入 `base64`，选择编码或解码，输入文本，执行 | 在 Spotlight 内显示并复制结果 |

本文中的“执行”默认指按回车。每敲一个字符就实时计算整个搜索词，不属于已确认能力。

## 官方能力与候选方案

macOS 26 的 Spotlight 可以运行 App Intents，必需参数需要能在参数摘要中填写。动作与参数模型是实现 A 的基础；后台执行和结果卡片用于完成处理后保持当前工作上下文。[Apple App Intents 说明](https://developer.apple.com/videos/play/wwdc2025/260/)

系统 Quick Keys 支持给动作设置关键词，并在关键词后附带参数。Apple 以 `ft Ashley` 为例说明这种流程。它为 B 提供了一条候选路线，但不能据此直接证明完整的 `base64 encode hello` 已可用。[macOS 26 Quick Keys 文档](https://support.apple.com/en-my/guide/mac-help/mchl4953dfeb/26/mac/26)

建议验证：提供“Base64 命令”动作，以一段文本作为参数；用户将它绑定到 `base64`；如果系统把 `encode hello` 原样交给动作，模块解析操作与载荷，然后调用共享引擎。

交互式结果可采用系统 Snippet 与复制动作。结果必须先计算一次，再把稳定值交给卡片展示，点击时复制该值。[Apple 交互式结果卡片](https://developer.apple.com/documentation/appintents/displaying-static-and-interactive-snippets)

## 尚未验证的关键问题

| 问题 | 为什么必须验证 |
| --- | --- |
| 是否允许完整关键词 `base64` | 文档示例不等于长度、数字字符和冲突规则已经确认 |
| 空格后的字符串是否整体传入 | 如果系统只取第一个词，B 的原文保留要求就不成立 |
| 粘贴、Unicode、多个空格和换行 | 不能把经系统改写的文本当作原始载荷 |
| `base64` 单独输入的 A/B 冲突 | 绑定 Quick Key 后，裸关键词可能直接进入命令动作，而非显示编码/解码选择 |
| 空参数及未知子命令的补充交互 | 需要知道能否在系统内选择操作、补充文本或显示语法帮助 |
| 点击整块结果复制 | 要测试真正的 Spotlight 卡片交互，不能只验证主窗口按钮 |
| 未运行、运行中、没有主窗口 | 三种生命周期下都要避免抢焦点并保证能完成动作 |
| 公开分发后的发现与更新 | 开发目录可发现不等于安装、签名和升级后的行为一致 |

上述问题是开发前的技术可行性关卡。当前已实现候选方案，系统实测遇到启动阻塞；不把候选方案记为已验收功能，详见 [验收记录](verification.md)。

## A 与 B 的共存设计

A 由语义明确的“Base64 编码”“Base64 解码”动作承载。B 可使用单独的“Base64 命令”动作解析短命令。操作名称、搜索关键词及首次引导需要防止用户选到错误入口。

同一个 `base64` 同时作为搜索词和 Quick Key，可能改变 A 的触发方式。验证时必须同时检查配置前、配置后两种状态。如果 A 需要额外按键或改用别名，先记录差异，再与用户确定是否接受；不能单方面宣称满足原交互。

若系统不允许指定关键词，可评估较短的 `b64`、独立的编码/解码关键词或保留 A。任何改变用户命令的方案都只是备选。应用自己的全局快捷面板不是当前已同意的替代品。

## 命令契约草案

完整用户表达为 `<tool> <operation> <payload>`。当系统 Quick Key 已识别工具时，适配器可能只收到 `<operation> <payload>`，因此命令解析应区分“系统已提供工具上下文”和“完整命令”，不能要求原文一定带有工具前缀。

| 输入 | 语义 |
| --- | --- |
| `base64 encode hello` | 编码文字 `hello` |
| `base64 encode hello world` | 编码文字 `hello world`，不是两次操作 |
| `base64 decode aGVsbG8=` | 解码为 `hello` |
| `base64 decode Zg` | 补全缺省填充并解码为 `f` |
| `base64 encode` | 参数不完整，提示输入文本，不自动处理剪贴板 |
| `base64 encod hello` | 未知操作，提示支持 encode/decode |

工具名与操作名可以不区分大小写；载荷大小写、内部空格和换行始终保留。解析器不执行 shell，不做变量展开，不对引号、反斜杠、百分号进行额外解释。

如需控制参数，建议使用 `--url-safe` 等明确选项，并以独立 `--` 分隔控制参数与载荷。分隔符后的一个约定分隔空格属于语法，其后的内容属于原文；载荷以连字符或前导空格开头时必须可无歧义表示。完整语法需在 Quick Keys 原文传递验证之后冻结。

空文本需要明确语法，建议 `base64 encode --`，避免把“忘记输入”与“编码空字符串”混为一谈。引号不默认充当终端引号，帮助中必须有示例。

## 结果与复制

结果包含工具名称、操作、结果预览、完整值长度和复制操作。主复制区应可通过鼠标点击和系统辅助功能激活；预览截断不改变复制值。解码结果中的不可见尾部换行可用标识解释，但不能把标识当成内容复制。

点击后显示“已复制”。复制只在这一动作中发生；重复显示卡片、系统刷新和窗口切换都不能覆盖剪贴板。多个结果同时存在时，按钮必须关联自己的结果，不能共享一个全局“最近输出”。

初始短命令建议限制为 16 KiB UTF-8 输入。超出时显示原因并引导用户在完整工具箱处理；主窗口接收数据的方式需单独设计，不能把密钥或大量内容未经说明写入磁盘或 URL。

## 入口筛选

首个贯通样例为 Base64，之后按 [工具目录](tool-catalog.md) 中的“快捷候选”逐项接入。JSON 格式化、时间戳、命名转换和生成器等只提供适合小输入的子能力。

多文件、图片编辑、正则调试、复杂结构比较和联网调试不强行搬入 Spotlight。能力筛选记录在工具描述中，而不是在系统入口里临时猜测。

## 验证证据要求

必须记录 macOS 版本、应用构建与安装方式、系统语言、Quick Key 配置、输入原文、输出原文和焦点表现。Base64 的复制结果以字节比较，覆盖用户给的末尾换行示例。

构建成功、元数据包含动作、快捷指令目录能看到动作、直接调用 `perform` 返回正确，都不足以证明 Spotlight 全流程完成。只有系统界面实测才能将该项标记通过。
