# DevKit 技术架构

## 架构目标

使用 Swift 构建原生 macOS 26+ 应用，以 SwiftUI 管理窗口、导航和系统风格；编辑器等需要更精细控制的组件可封装 AppKit。工具核心逻辑不依赖 SwiftUI、AppKit 或 Spotlight，从而能被主窗口、快捷动作和测试共享。

模块以功能目录组织，先采用结构清晰的单体应用。目录独立不等于必须为 72 个工具创建 72 个 Swift Package。只有在依赖隔离、复用或构建收益明确时，再将相应工具提取为独立构建模块。

## 分层与依赖

```text
AppShell                 窗口、菜单、导航、标签页、设置
  ├─ ToolRegistry        工具元数据、能力、视图和命令注册
  ├─ Tools/<id>/UI       工具页面及当前标签的会话状态
  └─ Integrations        系统动作入口和生命周期

Tools/<id>/UI ───────────────┐
Tools/<id>/Spotlight ────────┼─> Tools/<id>/Domain ─> Shared/Domain
Tests/<id> ─────────────────┘

需要副作用的 Domain ─> 能力协议 ─> 文件、剪贴板、网络或隔离执行服务
```

工具不能导入其他工具的页面或状态。跨工具处理通过类型明确的输入输出和显式“发送到工具”完成；可复用算法移到共享域层，而不是从某个工具的 UI 文件中调用。

下面是概念目录基线。当前实际构建目录见 [开发维护](development.md)，核心与 App 适配分属两个编译层。

```text

  Shared/

    UI/                  编辑器、结果列表、参数容器、系统样式封装
    Services/            文件、剪贴板、网络、隔离工作进程

    json/

    ...
  Integrations/
```

每个实际文件应带工具前缀，如 `Base64Engine.swift`，避免几十个 `ViewModel.swift` 难以搜索。只有确有内容时创建子目录；小工具不为满足模板而拆出空文件。

## 工具契约

工具描述至少包含稳定 ID、分类、本地化名称、别名、图标、输入类型、输出类型、能力需求、运行策略和可用入口。业务请求使用工具自己的强类型参数，不能用全局字符串字典承载所有工具配置。

引擎接收输入和参数，返回结构化结果或结构化错误。结果可能是文本、字节、列表、表格、图像、文件或带诊断的位置数据；公共结果视图通过这些类型选择呈现方式。

注册层可以做类型擦除以统一导航，但不能因此丢掉工具内部的输入约束。唯一 ID、别名冲突和命令歧义在构建或测试阶段检查。

## 状态管理

应用级状态只包含导航、标签列表、设置和能力服务。每个标签拥有独立的工具会话；每个工具定义自己的参数类型和状态，不在一个全局模型上增加几十个无关字段。

处理请求使用递增版本或请求标识。任务完成时校验当前会话和输入版本；取消或过期的任务不得修改结果。状态更新在 UI 线程，计算、文件读取和网络等待在合适的执行上下文。

输入结果默认仅在内存中。偏好存储只能持久化非敏感配置；网络凭证、JWT、密钥、正文不能混入通用状态恢复。

## 性能与隔离

长文本编辑采用受控尺寸的原生编辑组件，不按全文内容决定窗口高度。列表按需渲染，语法高亮与差异分析避免每次输入重算所有数据。

流式处理适用于文件摘要和大文件转换。取消必须有实际检查点；仅取消一个外层异步任务不代表同步解析器已经停止。

正则、解压、复杂格式解析和不可信预览需要明确资源上限。对无法可靠中断的执行器，考虑独立受限工作进程并使用超时终止；不能把它放进主线程，也不能宣称普通后台任务就解决了失控执行。

解析器、格式化器、图片库与隔离方式在对应批次前单独选型，记录 API/规范版本、许可证、维护状态及性能样本。当前选用的版本与许可证见开发维护文档。

## 原生系统集成

主窗口优先使用标准 SwiftUI/AppKit 导航与工具栏，以获得系统材质和行为；确需自定义时遵循 [视觉规范](visual-design.md)。[Apple 系统组件与 Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/liquid-glass)

Spotlight 使用可执行 App Intents 与交互式结果，不能只依赖 Core Spotlight 的内容索引。所有必填参数必须可由系统入口收集；动作以后台模式执行，不抢走主窗口焦点。[Apple Spotlight 与 App Intents](https://developer.apple.com/videos/play/wwdc2025/260/)

App Intents 的类型及参数是编译期描述，不能假设运行时注册一个字典就能自动得到系统动作。每个适用模块保存自己的动作适配文件，由应用级 App Shortcuts 汇总。复制和结果卡片使用公共实现，不复制粘贴业务算法。

## 构建与发布结构

计划使用原生 Xcode 应用 target 生成完整应用包、图标、本地化及系统动作元数据。纯核心逻辑是否额外提供 Swift Package，由测试与复用需要决定；不能只复制裸可执行文件就宣称完成 Spotlight 打包。

构建验证至少检查：最低系统版本、动作元数据、参数摘要、应用资源、架构和签名。Debug、Release、安装后的包分别验证，不能把开发目录中的可运行状态等同于可分发状态。

Apple Silicon 作为优先自用验证环境；公开发布是否同时提供 Intel 架构由实际需求、依赖能力和测试设备决定，不预先宣称通用架构已支持。

## 可维护性约束

- 新增工具只触碰自己的目录、注册表、测试及文档；大量修改已有工具通常说明边界需要调整。
- 共享组件只在多个实际工具需要同一种行为时提取，不预造一个无所不能的表单引擎。
- 文件大小不能成为唯一拆分标准，以职责、状态和依赖为依据拆分。
- 模块特有资源和示例留在模块内，通用系统样式统一维护。
- 处理日志不记录输入正文、输出正文或密钥；诊断使用操作 ID、耗时、大小和非敏感错误类别。
