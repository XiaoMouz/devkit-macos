# DevKit 模块开发规范

## 一个工具一个目录

工具目录中的每个 ID 对应 `Tools/<id>/`。编码与解码属于同一个工具，MD5 与 SHA 系列属于哈希工具的不同算法。不同责任的工具不能因为都处理字符串，就合并为一个巨大的“文本工具”文件。

建议文件布局如下，名称只是未来实现契约，不是当前代码：

```text
Tools/base64/
  Base64ToolDefinition.swift
  Domain/
    Base64Request.swift
    Base64Options.swift
    Base64Engine.swift
    Base64Error.swift
    Base64CommandParser.swift
  UI/
    Base64View.swift
    Base64Session.swift
  Spotlight/
    Base64EncodeIntent.swift
    Base64DecodeIntent.swift
    Base64CommandIntent.swift
  Resources/
  README.md
Tests/Tools/base64/
  Base64EngineTests.swift
  Base64CommandTests.swift
  Base64SessionTests.swift
```

简单工具允许将紧密相关的小型类型放在同一文件，但 UI、业务算法与系统动作不能全部混放。没有 Spotlight 能力的工具不创建空的 Spotlight 目录。

## 模块必须说明的内容

| 项目 | 必须回答的问题 |
| --- | --- |
| 标识 | 稳定 ID 是什么，名称和搜索别名是什么？ |
| 场景 | 用户为什么用它，与其他模块有什么区别？ |
| 输入 | 文本、字节、文件或结构化数据？编码、大小和数量限制是什么？ |
| 参数 | 每个参数的类型、默认值、允许范围及对结果的影响是什么？ |
| 输出 | 是否可能为空、二进制、多个项目或部分失败？ |
| 语义 | 采用哪一种标准、方言、时区、精度或字符统计口径？ |
| 状态 | 如何执行、取消、使旧结果失效，如何显示进度？ |
| 错误 | 如何定位问题，哪些错误可由用户修正？ |
| 副作用 | 是否读文件、写文件、联网或访问剪贴板？何时触发？ |
| 入口 | 工具箱布局模板是什么，是否适合 Spotlight？ |
| 验证 | 标准向量、边界、性能和 UI 用例是什么？ |
| 依赖 | 使用哪些库、版本、许可证和能力限制？ |

## 请求与结果约束

引擎必须接受完整的不可变请求快照，不能直接读取 UI 文本框、全局选中工具、系统剪贴板或用户默认设置。时间、随机源、文件和网络依赖通过明确的能力接口传入，便于验证。

原始输入与规范化后的数据分开处理，规范化策略属于模块参数。业务代码不能先统一 `trim` 后再处理所有字符串。

错误有稳定类别及可选位置；用户文案在显示层本地化。格式不正确、字符编码无效、超限、取消和内部故障要可区分。公共错误层不能吞掉工具特有诊断。

结果保留完整值，展示层可以做预览截断。结果格式、条目数和原始字节数来自结果对象，不能通过显示文本重新猜测；批量数据尤其不能简单按换行重新推断条数。

## Base64 模块样例规格

| 项目 | 规格 |
| --- | --- |
| 输入 | 默认 UTF-8 文本；文件/字节路径独立，不能把二进制强制显示为文本 |
| 操作 | encode 与 decode，必须明确选择，不自动猜测 |
| 字母表 | 标准与 URL Safe 显式选择 |
| 编码填充 | 默认保留 `=`，可选择省略 |
| 解码填充 | 支持完全省略末尾填充；不把任意错误的 `=` 序列默默修正 |
| 空白 | 编码保留原始空格/换行；解码允许文档指定的 ASCII 空白，不忽略其他非法字符 |
| 解码结果 | UTF-8 可直接显示；非 UTF-8 在主窗口提供字节/导出视图，在 Spotlight 明确提示改用工具箱 |
| 空文本 | 主窗口允许；命令入口需明确表示空载荷以免误把缺少参数当作空文本 |
| 复制 | 完整输出，包括尾部换行；不因界面隐藏换行而丢失字节 |
| 关键向量 | `hello` 编码为 `aGVsbG8=`；`Zg` 解码为 `f`；中文和 Emoji 可往返 |
| 用户样例 | `MTIzMTIzMTIzYXNkZmFkc2ZzZGFmCg` 解码为 `123123123asdfadsfsdaf` 加一个 LF 换行 |
| 错误 | 非法字母表、错误长度、错误填充、无效 UTF-8、输入超限分别提示 |

主窗口、Spotlight 引导动作、命令动作都调用同一 Base64 引擎。结果卡片的重复绘制不重复执行引擎，更不能再次访问剪贴板。

## 模块接入步骤

1. 在工具目录确认 ID、分类、批次及功能边界，补充模块 README。
2. 定义请求、参数、结果、错误及能力依赖，补充标准向量与边界测试。
3. 实现领域逻辑，再用已有模板组合页面和会话状态。
4. 在唯一工具注册表登记元数据、入口与能力；不得到处添加条件分支。
5. 如适合快捷操作，添加本模块的动作及命令适配，完成系统参数与结果规范。
6. 验证资源限制、取消、输入更新、复制、无障碍与窗口适配。
7. 完成模块文档和实际验收后，才在正式导航中标记可用。

## 测试与依赖规则

优先测试行为和外部规范，而不是复制实现细节。生成器测试约束和版本位，不用“连续生成从未重复”作为随机性证明。时间测试固定时区和参考时间；网络测试使用受控本地服务。

跨模块共享能力由统一服务提供。禁止从一个功能目录访问另一个目录的页面状态，禁止为修复一个工具而改变所有工具的默认语义。

新依赖必须记录用途、版本、许可证、维护状态、体积、线程安全和适用系统。JS/TS 格式化等复杂能力可以使用成熟组件，但不因此把所有工具迁入网页容器，也不在运行时从 CDN 获取执行代码。

## 完成条件

一个模块的完成记录应包含：实现范围、未支持格式、测试结果、界面截图或交互记录、性能样本、依赖说明与已知限制。工具目录的“完成”必须能找到这些证据；计划中的选项不能以可点击空按钮形式混入正式版本。
