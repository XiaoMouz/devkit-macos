# DevKit 视觉规范

> 2026-10-10 当前实现以本段及 [UI 修正记录](ui-refinement.md) 的最新记录为准。设计以 macOS 26/27 的 Apple 设计规范与开发文档为先，本仓库的早期约定与之冲突时以系统规范为准。窗口使用系统 `NavigationSplitView`、统一工具栏与 `.inspector`：侧栏是内缩的悬浮 Liquid Glass 面板，红绿灯由系统放置在面板顶部；工具名称是窗口标题（不显示说明副标题），操作模式位于工具栏中央，视图切换、窗口菜单、收藏与主操作位于工具栏右侧；配置在可收起的检查器中。编辑区是基础内容层，输入与结果在对照视图中顶部对齐。保留收藏，不设常用区或工具标签页。下文早期草案中的标签与参数弹层不再代表当前方案。


## 设计方向

采用苹果原生应用的视觉语言，结合开发工作台的操作密度。界面以系统导航、工具栏、文本与结果为中心，不做网页式大标题、品牌宣传区或大面积装饰卡片。应用使用自己的名称与图标。

辨识度来自“同一工具清晰的输入、操作、结果关系”：转换工具左右对照，生成工具配置与结果并排，短结果的复制入口随结果出现。各工具布局可以变化，但导航、状态与操作位置保持一致。

## Liquid Glass 的使用

优先采用系统工具栏、侧栏、菜单、弹出框和按钮样式，让材质、滚动边缘和交互随系统演进。Liquid Glass 用在导航与操作层，编辑正文及大面积结果背景使用清晰的内容表面。自定义玻璃效果只在有明确层级需求时引入，避免玻璃面板层层嵌套。[Apple 材质指南](https://developer.apple.com/design/human-interface-guidelines/materials)

应用跟随系统的浅色/深色、强调色、透明度及动态效果偏好；“减少透明度”和“减少动态效果”开启后，功能、状态区分和文字可读性仍成立。系统控件优先承担这些适配，自定义元素另行验收。[采用 Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

## 语义样式

| 角色 | 规范 |
| --- | --- |
| 应用背景 | 系统窗口背景，跟随外观 |
| 编辑区 | 系统文本背景；适合长时间阅读的稳定内容层 |
| 导航与浮动操作 | 系统材质及原生工具栏风格 |
| 主操作/选中 | 系统强调色，不能只靠颜色标记选中 |
| 正文与次级信息 | 系统标签颜色层级；重要说明不用低对比度浅灰 |
| 状态 | 系统语义色配合图标及文字，不用颜色单独表示成功或失败 |
| 字体 | 界面用系统字体；代码、命令、字节数据用系统等宽字体 |
| 图标 | 优先 SF Symbols，并为无文字按钮提供标签及悬停提示 |

不锁定一套浅色十六进制色值来模拟系统 UI。工具专属图表或颜色预览需要固定颜色时，应限定在内容层，并与应用强调色区分。

建议排版层级：窗口与工具标题 17–22 pt，正文与控件 12–14 pt，代码 12–14 pt，辅助信息 11–12 pt。优先使用系统文本样式及其对应缩放方式，不把示意数值当作每个控件的硬性高度。

## 窗口适配

当前最小窗口为 800×600。宽窗口采用可拖动的等分面板；内容宽度不足 720 pt 时切换为输入 / 结果大面板。双输入工具在窄窗口提供输入 / 第二输入 / 结果切换，生成器参数改为弹层。不能通过压缩字体或裁切底部按钮维持布局。

编辑器与结果列表在自己的区域滚动。窗口尺寸必须独立于文本内容的内部高度；百万字符输入不能把窗口撑出屏幕。分隔线可拖动，布局偏好按窗口保存。

原生全屏、窗口缩放、显示器切换以及系统窗口平铺需要验收。多标签与系统菜单、窗口管理配合，不重绘红黄绿控制按钮。

## 动效与反馈

只对切换、参数展开、执行状态和复制反馈提供短促的系统式过渡。没有持续发光、背景漂移或无意义的弹跳；减少动态效果时去掉非必要运动。

“已复制”反馈放在触发位置，避免弹出新的浮层遮挡结果。长任务有真实进度时显示比例，没有真实进度时只显示处理中，不模拟进度条。

## 视觉评审清单

评审覆盖浅色、深色、不同系统强调色、减少透明度、减少动态效果、键盘焦点、VoiceOver、长中文标题、长错误信息和窄窗口。

重点确认：玻璃只强调操作层；代码阅读清晰；72 个工具仍易查找；主操作无需滚动寻找；结果复制范围明确；系统控件没有被多余的背景或边框覆盖。
